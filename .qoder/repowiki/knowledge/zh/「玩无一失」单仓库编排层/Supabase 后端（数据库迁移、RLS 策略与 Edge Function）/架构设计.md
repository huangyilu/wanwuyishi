模块由三块组成，职责清晰且单向依赖：
- `migrations/*.sql`：按序号递增的幂等 SQL 迁移，0001_init.sql 一次性创建 profiles/trips/trip_members/trip_days/trip_items/item_votes/tickets/expenses/expense_shares/transports/accommodations/personal_notes/trip_invites/shares 等表、枚举类型、索引与触发器（如 on_auth_user_created、on_trip_created、updated_at 自动维护），并通过 SECURITY DEFINER 函数 public.is_trip_member / is_trip_owner 统一判定成员/主人身份，再为每张表启用 RLS 并定义 per-table policy；同时暴露 get_trip_bundle、join_trip_by_token、get_share、clone_trip_from_share、ping 等 RPC。
- `apply_attachments.sql`：独立幂等脚本，为 trip_items 增加 images text[] 列，创建 storage bucket trip-attachments（10MB、仅图片/PDF MIME），并配置 storage.objects 公开读 + authenticated 写/删 RLS，需手动在 Supabase SQL Editor 执行。
- `functions/chat-proxy/index.ts`：基于 Deno.serve 的 Supabase Edge Function，仅做 DeepSeek Chat Completions API 中继，从环境变量 DEEPSEEK_API_KEY 读取密钥，校验 authorization 头后转发请求，白名单限制 model 字段，默认 temperature=0.2、stream=false，错误透传上游状态码。
依赖方向：前端 → Supabase REST/RPC → DB (RLS)；Edge Function 单向调用外部 DeepSeek API，不直接访问业务表。
