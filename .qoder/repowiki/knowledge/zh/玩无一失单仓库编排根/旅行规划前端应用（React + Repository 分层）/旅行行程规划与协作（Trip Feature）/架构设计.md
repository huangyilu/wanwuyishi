模块以 `queries.ts` 为数据层入口：通过 `useTripRepo()` 获取 repo（本地 localStorage 或 Supabase），用 `@tanstack/react-query` 暴露 `useTrips`、`useTripBundle` 等查询 hook，并以 `useTripMutations(tripId)` 集中封装所有写操作；写操作统一走乐观更新——`onMutate` 直接修改缓存中的 `TripBundle`，`onError` 回滚，`onSettled` 失效 bundle 与 list key，保证拖拽等高频交互零延迟。

UI 层按设备/场景拆分：`Workbench.tsx` 是 PC 端三栏布局（世界库 / 时间线 / 详情面板），基于 `@dnd-kit/core` 的单一 `DndContext` 实现跨栏拖拽（从世界库拖入行程、行程内排序、跨天移动），并通过 CSS 变量驱动左右栏手动调宽；`Timeline.tsx` 是中间编辑区，使用 `SortableContext` + `useDroppable` 实现条目排序与日卡间互拖；`MobileTrip.tsx` / `MobileToday.tsx` 提供移动端“今天该干嘛”的只读视图。

子功能组件各自独立：`ItemEditor`、`TicketEditor`、`PackingPanel`、`VotePanel`、`ChatPanel`、`MapPanel`（懒加载）、`CollaborateDialog` / `JoinDialog`（协作邀请与加入）、`MemberAvatar`（成员头像堆叠）。状态共享依赖外部 store：`useWorkbench` 管理选中日期与 inspector（poi/item/none），`useMyMember` 根据当前登录用户 ID 在 members 中挑选“我”的成员记录，避免协作模式下误判 owner。

依赖方向单向向下：组件 → `queries.ts` → `../../data`（repo/types）→ `supabase-client`；附件上传由 `uploadAttachment.ts` 封装到 `trip-attachments` bucket，仅云端模式可用；样式全部采用 CSS Modules（`.module.css`），地图标记共用 `mapMarkers.css`。
