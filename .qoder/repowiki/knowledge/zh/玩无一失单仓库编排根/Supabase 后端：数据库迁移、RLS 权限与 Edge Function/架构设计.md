模块由三部分组成：
- `migrations/`：按序号递增的 SQL 迁移文件，0001_init.sql 一次性创建 profiles/trips/trip_members/trip_days/trip_items/item_votes/tickets/expenses/expense_shares/transports/accommodations/personal_notes/trip_invites/shares 等表、枚举类型、索引、触发器（如 on_auth_user_created、on_trip_created、updated_at 自动维护）；通过 `public.is_trip_member` / `is_trip_owner` 两个 SECURITY DEFINER 函数统一判定成员/主人身份，再为每张表启用 RLS 并定义 per-table policy；同时暴露 RPC：`get_trip_bundle`（一次性拉取行程全量数据）、`join_trip_by_token`（凭 token 加入并认领幽灵成员）、`get_share`（匿名按 slug 读取分享快照）、`clone_trip_from_share`（从分享快照克隆为新行程）、`ping`（保活）。
- `apply_attachments.sql`：独立幂等脚本，为 trip_items 增加 images text[] 列，创建 storage bucket `trip-attachments`（5MB、仅图片 MIME），并配置 storage.objects 的公开读 + authenticated 写/删 RLS。
- `functions/chat-proxy/index.ts`：基于 Deno.serve 的 Supabase Edge Function，仅做 DeepSeek API 中继，从环境变量读取 DEEPSEEK_API_KEY，校验 authorization 头后转发请求到 https://api.deepseek.com/chat/completions，白名单限制 model 字段，默认 temperature=0.2、stream=false，错误透传上游状态码。
依赖方向：前端 → Supabase REST/RPC → DB (RLS)；Edge Function 单向调用外部 DeepSeek API，不直接访问业务表。
