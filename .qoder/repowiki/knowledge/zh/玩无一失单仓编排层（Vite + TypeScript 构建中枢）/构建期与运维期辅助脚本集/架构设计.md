脚本按职责划分为四类，均通过 Node.js（TS/ESM/CJS）或 Bash 直接执行：
- 内容管线：`content-io.ts` 作为共享 I/O 层，统一从 `content/{countries,cities,pois}` 读取 JSON 并用 `src/domain/world/schema.js` 中的 Zod schema 解析；`build-index.ts` 消费该层产出 `public/data/{index,country,city,poi,search,aliases}.json`；`validate-content.ts` 在此基础上叠加业务规则校验并输出 error/warn 退出码。
- 地图瓦片：`build-pmtiles.sh` 在 `.tilebuild` 缓存目录中按需下载 Adoptium JDK 21、protomaps pmtiles 二进制与 Planetiler jar，调用 Geofabrik 数据为法/意/瑞三国分别生成 pmtiles 后合并为 `public/tiles.pmtiles`。
- 图片采集：`fetch-city-images.mjs` / `fetch-new-images.mjs` / `fetch-poi-images.mjs` / `fetch-south-france-images.sh` 通过 curl 调用 Wikimedia Commons API，按许可白名单筛选并以 `{id}.jpg` 写入 `public/img/{cities,pois}`，同时维护 `credits.json` 署名元数据；`fix-images.mjs` 用更精确的搜索词覆盖已有配图。
- 后端验证：`verify-supabase.cjs` 与 `verify-password-login.cjs` 直接读取根目录 `.env` 构造 Supabase 客户端，执行匿名登录→建行程→RPC 读取→清理的闭环测试。
依赖方向单向：所有脚本仅依赖 `src/domain/world/schema.js` 的类型与校验函数，不反向依赖应用运行时代码。
