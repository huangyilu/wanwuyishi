根目录作为单仓库多模块编排层：`package.json` 的 `scripts` 将 `content:validate` → `content:build` → `tsc -b` → `vitest run` → `vite build` 串成固定顺序，使 content_data 的 JSON 源在每次构建前被校验并生成索引，再由 frontend_app 消费；`tsconfig.json` 通过 `baseUrl` + `paths: { '@/*': ['src/*'] }` 让 frontend_app 与 build_scripts 共享同一路径别名并在同一类型检查任务中编译；`vite.config.ts` 设置 `base: './'`、`resolve.alias['@']` 以及按 react/react-query 拆分 manualChunks，使产物可直接部署到 GitHub Pages 子路径并支持离线 `file://` 访问；`.github/workflows/deploy.yml` 在 push main 时注入 `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` 环境变量完成 Supabase 前端的静态构建与 Pages 发布。各子模块之间无运行时耦合，仅通过 npm scripts、共享 ts/vite 配置与生成的 index 数据协作。
